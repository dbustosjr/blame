## 1. Project overview

Blame is a coding agent built on Pi, shipped as a VS Code extension (VS Code, Cursor, Windsurf) and a terminal app, with a learning record that proves the agent stops repeating mistakes, a second brain injected before every task, and an independent reviewer (F24) for every agent PR. Users bring their own model keys. The backend is small: Postgres (pgvector plus full-text search) on InsForge, a FastAPI service, a GitHub App and an MCP server. Everything that touches source code runs on the user's machine or in the user's own GitHub Actions by default.

## 2. Technical goals

| TG-6 | $0 per month at pilot scale | Fits InsForge Free, GitHub Free, and the user's own model keys. First paid step and its trigger are written down (section 8) |

## 4. Functional requirements

Grouped by area. Each line is observable behavior and names the PRD feature it serves.

### 4.1 Agent core (`packages/core`)

- FR-CORE-1: `createBlameSession(opts)` starts a Pi `AgentSession` with Blame's extension set loaded (context injection, autonomy gate, audit, checkpoints, guardrails, redaction). Both CLI and extension call only this (TG-1).
- FR-CORE-2: Before every run, the `before_agent_start` hook calls `getContext(task, paths)` and injects Confirmed lessons and knowledge items as one custom message with source links (F6). Under 1.5 s p90 (R-PERF-1); on timeout the run continues and the UI shows "context unavailable".
- FR-CORE-3: Every tool call passes through the `tool_call` hook, which evaluates the autonomy policy (section 4.4) and returns allow, ask or block. Blocked and asked calls are audit events (F4).
- FR-CORE-4: Bug tasks follow reproduce-before-fix: the agent must produce a failing test or script and a recorded failing run before the gate allows any edit outside test paths (F8).
- FR-CORE-5: Checkpoints are commits on the agent branch `blame/<task-slug>` or, if the user disables commits, refs under `refs/blame/checkpoints/<session>/<n>`. Rewind restores the tree exactly (hash check) and never touches the user's uncommitted work without asking (F10).
- FR-CORE-6: Budget and loop guardrails: per-task USD budget from Pi token accounting, hard stop, loop rule from PRD F15 (same failing test with same error 3 times, or 2 identical checkpoint diffs) (F15).
- FR-CORE-7: Docs-first: read pinned versions from lock files, fetch docs (Context7, then official page), cite URL and version in the PR body (F11).
- FR-CORE-8: Secret redaction runs on every tool result before it enters model context, logs or the learning record. `.env*` and files matched by gitleaks rules are excluded from context by default (F17).
- FR-CORE-9: gitleaks runs before every agent commit; a hit blocks the commit (F17, R-SEC-6).
- FR-CORE-10: PR bodies contain summary, plan, tests added, lessons applied, docs cited, cost (F9).

### 4.2 Learning record and brain

- FR-BRAIN-1: A failure (revert, unmerged close, changes requested, CI failure on agent branch, denied approval, confirmed F24 finding, user "that was wrong") becomes a `failure` knowledge item with evidence excerpts bound to repo, PR and head SHA (F3).
- FR-BRAIN-2: Blame drafts a lesson and a regression test. No lesson becomes Confirmed or Active without human approval (F3).
- FR-BRAIN-3: Before saving any item, dedupe runs (hybrid similarity above threshold) and proposes a merge instead of a duplicate (F6).
- FR-BRAIN-4: Items anchored to files are flagged stale when the anchored content hash changes past the threshold (F6).
- FR-BRAIN-5: Exposure, avoidance and recurrence events are recorded per lesson; proof status follows PRD 13.2 exactly. The chart endpoint returns the denominator (all Confirmed lessons) (F3, TG-5).
- FR-BRAIN-6: `blame export` writes markdown files plus a generated `AGENTS.md`; importing into an empty project restores Confirmed items and links (F6).
- Detail: [REVIEWER_AND_BRAIN.md](REVIEWER_AND_BRAIN.md).

### 4.3 Reviewer (F24)

- FR-REV-1: Every PR in a connected repo (any author) gets a review when opened or updated, by the `blame-review` GitHub Action in the user's repo with the user's key ([ADR-0004](adr/0004-reviewer-runtime.md)). Target under 5 min p90 for PRs under 500 changed lines (R-PERF-3).
- FR-REV-2: Findings carry exact path, line range, severity, category, rationale and evidence refs. Posted as PR review comments. Each comment has a "Fix with agent" link (`vscode://` URI for the extension, `blame fix <finding-id>` for CLI, copy-ready prompt for other agents).
- FR-REV-3: A confirmed finding (human reaction or the fix merges) creates a failure item and a draft lesson linked to the PR and finding.
- FR-REV-4: `blame review` runs the same reviewer locally before push.

### 4.4 Autonomy and trust (F2, F18, R-AUTO)

Both concepts are data, not code constants:

- `trust_levels` rows (seeded L0 to L4 from PRD F2) carry a capability set.
- `autonomy_presets` rows (seeded Manual, Guided, Autonomous) carry a ceiling level and an approval policy.
- Earned trust is stored per agent, per repo, per task class (`agent_trust`).

Effective permission for a tool call (R-AUTO-2): `min(preset.ceiling, earned level for this task class)`, then safe zones (always ask, no override, R-AUTO-3), then budget, then credential scope. Every check must pass.

| Preset (seed) | Ceiling | Approval policy | Sandbox profile |
|---|---|---|---|
| Manual | L1 | Ask for every edit and command | Read-only; writes only after approval |
| Guided (default) | L2 | Low-risk steps automatic (checkpoints, lessons, tests, allow-listed commands); ask for risky steps | Writes limited to workspace; egress only to model provider and docs hosts |
| Autonomous (opt-in per workspace) | L3 (L4 Later) | Ask only for safe zones and risky-action classes | Full `srt` profile: workspace-only writes, egress allow-list, CPU, memory and time limits. Refuses to start without sandbox |

Naming note: docs use "Guided" and `--mode guided` to match PRD v0.2. David confirmed Guided as the final name on 2026-11-13 (OQ-6, resolved).

Capabilities used by the gate (from PRD F2): `read`, `run_tests`, `edit_workspace`, `open_draft_pr`, `run_allowlisted`, `open_pr`, `edit_ci`, `edit_deps`, `network_sandbox`, `deploy_preview`. Risky-action classes (always at least "ask" below L3): `migration`, `delete_outside_branch`, `secret_access`, `egress_outside_allowlist`, `ci_change`, `force_push`.

- FR-AUTO-1: Promotion rule is configuration (`trust_policy` JSON per org): Proposal N = 10 merged PRs with zero reverts in 30 days per task class; a revert drops one level. Every change writes a `trust_events` row with the reason.
- FR-AUTO-2: Preset changes take effect on the next tool call without restart (F23.1) and write an audit event (R-AUTO-6).
- FR-AUTO-3: If David chooses a different number of levels or presets, only seed data and the theme ramp change; no code branches on level numbers. A unit test loads a 3-level fixture and a 5-level fixture to prove it.

### 4.5 Auth and keys (R-BYOK)

- FR-KEY-1: API keys entered in the extension go to `context.secrets` (VS Code SecretStorage). In the CLI they go to the OS keychain via `@napi-rs/keyring`. On Linux without a secret service, the CLI uses environment variables and refuses to write a plaintext file unless the user passes `--insecure-file-store`.
- FR-KEY-2: Keys reach Pi through a custom `CredentialStore` (Pi's `pi-ai` interface) or `ModelRuntime.setRuntimeApiKey()`, so Pi never writes `auth.json` for Blame. Spike in Phase 1 confirms the OAuth refresh path works with the custom store; fallback is an `auth.json` under Blame's config dir with mode 0600, documented as a known gap.
- FR-KEY-3: "Sign in with ChatGPT" uses Pi's `openai-chatgpt` OAuth flow (PKCE, loopback callback). Tokens stay on the device. OpenAI lists Pi among open-source integrations ([ChatGPT Learn](https://learn.chatgpt.com/docs/sign-in-with-chatgpt)); paid or remotely hosted apps must apply through OpenAI's interest form ([OpenAI developers](https://developers.openai.com/siwc/token-sharing-open-source)). See open question OQ-2.
- FR-KEY-4: Anthropic is API key only. Pi ships an Anthropic Claude Pro/Max OAuth module (`packages/ai/src/auth/oauth/anthropic.ts`); Blame disables that login method and hides it from `/login`. Anthropic's terms: "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users" ([Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)). A test asserts the method is absent.
- FR-KEY-5: Blame account login (CLI and extension) uses an OAuth device flow against the Blame API. Access tokens live 15 minutes; refresh tokens rotate on use and are stored in the keychain or SecretStorage.
- FR-KEY-6: Revoke (`blame revoke`, extension command, `POST /v1/agents/{id}/revoke`) deletes local keys, revokes Blame refresh and MCP tokens server-side (immediate, checked on every request), calls `DELETE /installation/token` for any installation token the server holds ([GitHub REST](https://docs.github.com/en/rest/apps/installations#revoke-an-installation-access-token)), and lists each step with its time. The UI shows "revoked", "requested" or "expires at" honestly per credential (F5).

### 4.6 Surfaces

- FR-CLI-1: `blame` opens the interactive TUI; `blame run "task" --mode guided --json` runs non-interactively with JSONL events (`--mode` is `manual`, `guided` or `autonomous`); `blame review`, `blame fix <id>`, `blame lessons`, `blame export`, `blame revoke`, `blame mcp` (stdio MCP server) exist (F23.2).
- FR-CLI-2: `NO_COLOR` and non-TTY produce plain output (R-A11Y).
- FR-EXT-1: Extension activation registers commands only (under 1 s, R-PERF-5). The core runs in a child process (ARCHITECTURE section 4) so a crash never takes down the extension host.
- FR-EXT-2: Chat panel, per-hunk accept or reject, preset toggle in panel header and status bar, trust badge, proof view, checkpoint timeline, approval prompts, `vscode://` handler for "Fix with agent" (F23.1).
- FR-EXT-3: Published to VS Code Marketplace (`@vscode/vsce`) and Open VSX (`ovsx`) from the same VSIX in one release workflow.
- FR-WEB-1: Website: install pages for both surfaces, BYOK and ChatGPT explanation, data and retention page (R-RET-1), opt-in public proof page (F23.3).

## 5. API contracts

### 5.1 REST (FastAPI, base `/v1`)

Conventions: OpenAPI 3.1 is the contract and is checked into `apps/api/openapi.json`; CI fails on an unreviewed diff. Errors use RFC 9457 `application/problem+json`. Every POST that creates or changes state accepts `Idempotency-Key` (stored 24 h). Cursor pagination (`?cursor=&limit=`, max 100). Versioning by path; breaking changes go to `/v2` with a 90-day overlap. Auth: `Authorization: Bearer <access token>` for CLI, extension, Action and MCP; HttpOnly session cookie for the website. The server derives the org from the token and membership, never from a request body (R-SEC).

| Method | Path | Purpose | Body or query | Response |
|---|---|---|---|---|
| POST | /auth/device/start | Start device login | `{client: "cli"\|"vscode"}` | `{device_code, user_code, verification_uri, interval}` |
| POST | /auth/device/poll | Finish device login | `{device_code}` | `{access_token, refresh_token, expires_in}` |
| POST | /auth/refresh | Rotate refresh token | `{refresh_token}` | new pair; old refresh token invalid |
| POST | /auth/actions-oidc | Exchange a GitHub Actions OIDC token for a 10-minute repo-scoped token | `{oidc_token}` | `{access_token, repo_id, scopes}` |
| POST | /auth/logout | Revoke current refresh token | none | 204 |
| GET | /me | User and orgs | none | `{user, orgs}` |
| POST | /orgs | Create org | `{name}` | `{org}` |
| GET | /repos | Connected repos | none | `{repos}` |
| DELETE | /repos/{id} | Disconnect and purge repo data (R-RET-6) | none | `{purge_job_id}` |
| POST | /github/install/callback | Bind a GitHub App installation to the caller's org (signed `state`) | `{installation_id, state}` | `{repos}` |
| GET | /trust-levels | Level definitions | none | `{levels}` |

| PATCH | /knowledge-items/{id} | Edit, confirm, supersede | `{title?, body?, status?, superseded_by?}` | `{item}` |
| POST | /knowledge-items/{id}/merge | Merge into target | `{target_id}` | `{item}` |
| POST | /links | Link items or external refs | `{from_id, to_id?, to_ref?, relation}` | `{link}` |
| POST | /failures | Record failure with evidence | `FailureIn` | `{failure_id, lesson_candidates}` |
| POST | /lessons/{id}/events | Exposure, applied, avoided, recurred | `{event, task_ref, head_sha, evidence_ref}` | `{lesson}` |
| GET | /metrics/never-repeated | Chart series | `?repo_id&from&to` | `{series, denominator, rule_version}` |
| POST | /reviews | Runner registers a review run | `{repo_id, pr_number, head_sha, base_sha, runner, model}` | `{review_id}` (idempotent on repo, PR, head SHA) |
| POST | /reviews/{id}/findings | Upload findings | `{findings: [FindingIn]}` | `{findings}` |
| PATCH | /findings/{id} | Confirm, dismiss, mark fixed | `{status, note?}` | `{finding}` |
| GET | /reviews | Review history | `?repo_id&pr_number` | `{reviews}` |
| GET/POST/DELETE | /repos/{id}/safe-zones | Manage safe zones | `{pattern, reason}` | `{safe_zones}` |
| POST | /events:batch | Upload audit events from clients | `{events: [EventIn]}` max 500 | `{accepted}` |
| GET | /events | Export audit log | `?agent_id&kind&from&to&format=jsonl` | JSONL stream |
| GET | /export | Brain as markdown plus `AGENTS.md` | `?repo_id` | zip |
| DELETE | /orgs/{id} | Delete account data (R-RET-7) | none | `{deletion_job_id}` |

Webhooks: `POST https://<insforge-functions>/github-webhook` (edge function). Verifies `X-Hub-Signature-256` on the raw body with a constant-time compare, dedupes on `X-GitHub-Delivery`, writes a `jobs` row, returns 2xx. GitHub expects a response within 10 seconds and reuses the delivery ID on redelivery ([GitHub best practices](https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks)).

Core shapes (Pydantic and TypeScript generated from the same OpenAPI):

```ts
type ContextItem = { id: string; kind: "lesson"|"decision"|"fix"|"incident"|"skill"|"failure";
  title: string; body: string; source_quote: string; source_url: string;
  scope_paths: string[]; score: number; reason: "path_match"|"hybrid"|"both" };
type FindingIn = { path: string; start_line: number; end_line: number;
  severity: "high"|"medium"|"low"; category: string; title: string; body: string;
  evidence: { kind: "file"|"lesson"|"past_bug"|"test"; ref: string }[]; confidence: number };

  "denied_approval"|"review_finding"|"user_report"; summary: string; head_sha: string;
  pr_number?: number; evidence: { kind: string; excerpt: string; url?: string }[] };
```

### 5.2 MCP tools (F23.4)

Two transports: `blame mcp` (stdio, recommended for Cursor and Claude Code; reads short-lived tokens from the keychain and refreshes them itself, so no long-lived secret sits in `mcp.json`) and Streamable HTTP at `/mcp` on the API with a bearer token from `POST /tokens` (max TTL 1 h). Tool outputs are data for the calling model. Text from the brain is wrapped and labeled as untrusted repository content.

| Tool | Input schema | Output | Notes |
|---|---|---|---|
| `get_context` | `{repo: string, task: string, paths?: string[], limit?: number (default 8, max 20)}` | `{items: ContextItem[]}` | Same ranking as the Pi hook (PRD F6 acceptance) |
| `search_brain` | `{query: string, repo?: string, kind?: string, limit?: number}` | `{items: ContextItem[]}` | Confirmed only unless `include_drafts` |
| `record_failure` | `{repo: string, kind: FailureIn.kind, summary: string, evidence: [...], head_sha?: string}` | `{failure_id: string, status: "draft"}` | Creates Draft only; humans confirm |
| `check_action` | `{repo: string, action_kind: string, target: string}` | `{decision: "allow"\|"ask"\|"deny", reason: string, safe_zone?: string}` | **Advisory** in companion mode: we cannot block another vendor's tool call (PRD 6.1) |
| `get_review_finding` | `{finding_id: string}` | `{finding: FindingIn, pr_url, head_sha}` | Lets another agent fetch an exact finding for "Fix with agent" |

### 6.1 Production readiness

- Tier: T1 "real users, small scale" (PRD 8.8): 5 design partners, under 50 repos, under 1,000 tasks a month.
- Patterns chosen: Postgres-backed job queue (`FOR UPDATE SKIP LOCKED`), idempotency keys, webhook dedupe, outbox for GitHub writes, structured logs with request IDs.
- Deferred, with triggers: Redis (queue p95 wait over 30 s), dedicated vector DB (brain over 1M items or search p90 over 500 ms), hosted sandbox (first paying team that needs remote tasks), events partitioning (events table over 10M rows).

## 8. Constraints

- C-1 Free tiers, verified Nov 13, 2026. InsForge Free: 500 MB database, 5 GB bandwidth, 100,000 edge function calls, 600 site build minutes, 120 hours a month of custom compute on the default spec, and free projects pause after one week of inactivity ([InsForge pricing](https://insforge.dev/pricing)). pgvector is included ([docs](https://docs.insforge.dev/core-concepts/database/pgvector)). Custom compute runs any Docker image as a long-lived container with no persistent volumes ([docs](https://docs.insforge.dev/core-concepts/compute/overview)). **Consequence (W0-1 answer):** a month is about 730 hours, so 120 hours cannot keep FastAPI always on. Webhooks therefore land in an edge function, heavy work runs in the user's Action, and the FastAPI container is sized for the remaining light traffic. Whether InsForge custom compute can scale to zero between requests is not documented; see OQ-4. First paid step: InsForge Pro, $25 a month month-to-month, with custom compute billed by usage ([pricing](https://insforge.dev/pricing)). Trigger: FastAPI needs more than 120 h a month, or the database passes 400 MB.
- C-2 GitHub Free includes $12 of Actions compute a month for private repos; a standard 2-core Linux runner costs $0.006 per minute, which works out to 2,000 minutes. Public repos run free ([GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions)). The reviewer Action spends the user's allowance, not David's.
- C-3 Branch protection and rulesets on private repos need GitHub Pro, Team or Enterprise ([GitHub docs](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)). For `dbustosjr/blame` this means branch protection on `main` needs GitHub Pro (OQ-3). For users on free private repos, Blame cannot rely on rulesets; its own enforcement is that the agent only pushes `blame/*` branches and opens PRs.
- C-4 Pi has no built-in permission system ([Pi README](https://github.com/earendil-works/pi#permissions--containerization)). Blame's `tool_call` gate is UX and audit; the sandbox is the boundary (TG-2).
- C-5 Force-push only to branches matching `blame/*` that Blame created and recorded; never the default branch, never a branch with an open human review without asking.
